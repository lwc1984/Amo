**Goal:** 一块放在桌角、余光扫一眼就知道"要不要走过去"的 ESP32 显示器，通过 mDNS 发现宿主机、配对后轮询 `/api/tiny`，用发光面积和颜色编码四种状态。

**Architecture:** 板级层用 ESP-IDF 内置的 `esp_lcd`（ST7789 + i80 是官方支持），
`components/tds3_board` 只有引脚定义与初始化，**无 vendored 代码**。其余全部自己写：
解析、主机表、发现、配对、轮询、UI 各占一个聚焦文件。所有纯逻辑（三行解析、主机表增删、状态判定）不依赖 ESP 头文件，因此能用主机 gcc 编译成可执行文件直接跑测试，不必等硬件。

**Tech Stack:** ESP-IDF v5.2.3（内置 esp_lcd）、LVGL 8.3.11（component manager）、esp_http_client、mdns、nvs_flash、lv_font_conv（node）

**Spec:** `docs/superpowers/specs/2026-08-18-agent-dashboard-design.md`（§5 是本计划的权威）

## Global Constraints

以下取值来自 spec 与实测，每个任务的要求都隐含包含本节。

### 硬件事实（2026-08-19 在实物上实测确认，权威见 spec §5.1）

- **LilyGo T-Display S3**，ESP32-S3R8 / 16MB Flash / 8MB OPI PSRAM
- 屏驱 **ST7789**，物理 170×320，**本项目用横屏 320×170**
- **8 位 I8080 并口**：D0-D7 = 39,40,41,42,45,46,47,48；WR=8, RD=9（须常高）, DC=7, CS=6, RST=5，pclk 10MHz
- **总电源使能 GPIO15**（不拉高屏幕完全不工作）；**背光 GPIO38**（纯开关，调光需 LEDC PWM）
- 面板列偏移 35（面板 170 宽、控制器 240 宽），横屏后落在 y 轴
- 按键：GPIO0 是 BOOT strapping 脚，**不用**；用 **GPIO14**
- **无 PMU、无触摸、无 RGB 灯、无蜂鸣器**

三个软件坑（详见 spec §5.1 与 `components/tds3_board/tds3_board.c` 的注释）：
颜色字节序须设 `.flags.swap_color_bytes`、`esp_lcd_panel_draw_bitmap()` 是异步的、
IDF 自带 st7789 驱动需补厂商初始化表。另：`sdkconfig.defaults` 与 `partitions.csv`
必须纯 ASCII，否则中文 Windows 上 `kconfgen` 直接炸。

### 语义色与文案（与宿主端逐字一致）

- run `#3FBFD8` / wait `#FFB020` / idle `#4A5B78` / stale `#E2564A`
- 状态短文案取自 `phrases.py:STATE_LABEL_SHORT`：waiting `该你了`／running `干着呢`／idle `摸鱼中`／stale `没声儿了`
- 连不上任何主机是**第五种**显示态，文案 `连不上`，与 `没声儿了`（服务端说某会话失联）语义不同，不得合并

### 协议

- `GET /api/tiny?k=<token>` 返回严格三行：`版本|w,r,i|主机名` / `会话名\tdetail` / `cpu,mem,gpu,net_kb`
- 无 GPU 时 gpu 为 `-1`；第二行无会话时为空行
- `?d=full` 才给完整参数，默认脱敏到工具名；**任何情况下都不下发 cwd**
- `POST /api/pair` 仅在宿主开启的 60 秒窗口内返回 `{"token","host_id","host"}`，否则 403
- mDNS 服务类型 `_agentdash._tcp.local.`，TXT 只含 `v` / `host` / `id`

### 亮度与告警

- 空闲 20/255、运行 60/255、等待 255/255 + 呼吸；AMOLED 黑像素不通电，空闲态功耗接近熄屏
- 告警仅在**进入** waiting 的那一次触发，不在持续期间反复
- 无蜂鸣器：告警用 WS2812 琥珀呼吸 + 屏幕拉满。可选外接无源蜂鸣器 `CONFIG_AGENT_BUZZER_GPIO`，默认 `-1`（关闭），建议 GPIO17

## 各任务实际做成了什么

正文（Task 0-10 的逐步指令）已删除。它整篇基于错误的硬件型号，照着做会产出
用不了的代码 —— 而顶部公告挡不住跳着看的人，**一份充满看似合理的错误指令的文档
比没有文档更糟**。完整原文在 git 历史里：

```bash
git log --oneline -- docs/superpowers/plans/2026-08-18-esp32-display.md
git show <commit>:docs/superpowers/plans/2026-08-18-esp32-display.md
```

下面是每个任务最终的落点与值得记住的结论。**权威是代码**，每处偏离计划的地方
都写在对应的提交信息里。

### Task 0 — 构建环境与官方仓库探针

结论已作废：我们不再依赖 `LilyGo-Display-IDF`。当时的发现仍记在
`amo-display/README.md` 的「历史」一节：官方声称要 IDF 5.3，但唯一的拦路石是
子模块 `SensorLib` 一行过时的 `REQUIRES esp_driver_gpio`，去掉那个词 5.2.3 就能
编过整仓 1426 个目标。

### Task 1 — `/api/tiny` 三行解析

`amo-display/main/tiny_parse.{c,h}`，40 条断言。纯 C、不含 ESP 头文件，
因此能用主机 gcc 直接跑测试，板子不在手边时这是唯一能验证的部分。

协议后来两次升版：v2 加 stale 计数、v3 加 busy 计数。版本号在这里两次发挥了
被设计出来的作用 —— 老固件见到不认识的版本整体拒绝，显示「连不上」而不是一个
错的状态。

### Task 2 — 已配对主机表

`amo-display/main/hosts.{c,h}`，22 条断言。按 `host_id` 而非 IP 去重：IP 会随
DHCP 变，`host_id` 是宿主端持久化的。`hosts_set_addr` 只动地址不动令牌 ——
mDNS 发现事件不该有能力冲掉配对时拿到的凭证。

### Task 3 — 工程骨架与板级组件

**整个重做。** 板子实为 T-Display S3（ST7789 / i80 并口 / 170×320 / 无 PMU），
不是计划假设的 AMOLED Lite。见 spec §5.1。

净收益：ST7789 + i80 是 ESP-IDF 内置支持，`components/tds3_board/` 约 150 行、
**vendored 代码为零**。原方案要拷十个文件加 XPowersLib，还要自己补 `extern "C"`、
维护 UPSTREAM.md、持续跟上游同步。

三个只有真机才会暴露的坑，都写在 `tds3_board.c` 的注释里：颜色字节序、
`draw_bitmap` 是异步的、IDF 自带 st7789 驱动需补厂商初始化表。

### Task 4 — 中文字库

`components/agent_ui/fonts/`，产物签入仓库，构建机不需要 node。
GB2312 一级汉字 + 区 01/03 标点，共 3942 字。

两次踩坑：标点最初漏了（区 01 不在一级汉字里），屏幕上每句话都长方框；
`lv_font_conv` 默认压缩字形位图，而 `LV_USE_FONT_COMPRESSED` 没开时 LVGL
**静默什么都不画** —— 内置 Montserrat 是非压缩的、照常显示，反而掩盖了原因。

### Task 5 — 文案防漂移

`tests/test_firmware_copy.py`。浏览器 JS 与固件 C 都没法 `import phrases.py`，
这个跨语言测试是唯一的强制手段。

它自己也有过洞：状态映射曾是手写固定表，加新状态不会自动纳入 —— **守卫看起来
在守、实际漏了**，这是防漂移测试最危险的失效形态。现已改为从 `phrases` 反推，
并加了守卫的守卫。另新增一条：28px 字库的字符表必须覆盖所有 `UI_S_*`。

### Task 6 — WiFi 与 mDNS 发现

`main/net_wifi.c`、`main/discovery.c`。两处实测才发现的问题：

- **必须关 WiFi 省电**。默认 `WIFI_PS_MIN_MODEM` 会让站点周期性休眠，而 mDNS 走
  组播、组播帧由 AP 按 DTIM 缓冲下发，休眠中的站点容易整帧错过。症状极具迷惑性：
  刚连上时正常，空闲两三分钟后同样的查询一台都扫不到。
- **单次 mDNS 查询本身不可靠**。同样的代码同样的网络，三次扫描可能是 1/0/1。
  重试放在 `discovery_scan` 内部 —— 不可靠是 mDNS 的固有属性，不是调用方的问题。

`mdns_init()` 必须在 `net_wifi_start()` 之后：它依赖 netif 与默认事件循环，
顺序反了返回 `ESP_FAIL`，而报错完全不提是缺了 netif。

### Task 7 — 配对与 NVS 持久化

`main/pairing.c`、`main/hosts_nvs.c`、`main/buttons.c`。按键 GPIO14（不是计划写的
GPIO21）。开机按住两秒清空配对。

**信任模型的核心已实测**：配对窗口没开时 `/api/pair` 返回 403，开着时成功。
发现得到但拿不到令牌 —— 同事的机器在 mDNS 上一样可见，没有那 60 秒窗口就什么
都读不到。

`net_wifi_start()` 里的 NVS 样板在分区满时会抹掉**整个 NVS**（含配对与令牌），
原本一声不吭。现已改为大声报错 —— 否则表现是某天开机突然"连不上"，
而没人会想到是这里。

### Task 8 — 轮询与聚合视图

`main/poller.c`。`view_build` 是纯函数，21 条断言在主机上跑。

状态优先级统一为 **等待 > 失联 > 憋大招 > 运行 > 摸鱼**，三处同序：
`sessions._ORDER`、`tray.overall_state`、`view_build`。此前 `_ORDER` 与
`overall_state` 不一致 —— 同一台机器，托盘和列表对"最该看哪条"的判断不同。

### Task 9 — UI

**完全重做成小怪物的嘴。** 这块屏嵌进了 3D 打印外壳的嘴部开口，所以它不是
显示器而是一张脸。六种状态六种嘴型，见 spec §5.3。

配套做出两个工具，都在 `amo-display/README.md` 里：串口抓帧还原 PNG
（人看不到屏幕时验证 UI 的唯一办法，当场抓出三个只看日志发现不了的问题），
以及 UI 演示模式（idle 与 nolink 在真实环境里几乎凑不出来，但同样需要被看过一眼）。

### Task 10 — 清理与文档

删掉作废的 `agent_display.ino`；spec §5 按实物重写；`README.md`、`CLAUDE.md`、
`amo-display/README.md` 更新到当前实现；本文件正文压成上面这份索引。
